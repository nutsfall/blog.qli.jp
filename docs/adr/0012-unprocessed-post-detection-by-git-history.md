# ADR-0012: 未処理記事の判定はgit履歴（インポートbotしか触っていない）で行う

- ステータス: 採用
- 日付: 2026-08-11

## コンテキスト

`process_new_posts.rb` の処理対象は「`source: medium` かつ 本文にMedium画像URLか計測ピクセルが残っている記事」だった。画像の有無が「インポートされたまま未処理」のプロキシとして機能していた。

しかしこのスクリプトの仕事は画像のローカル化だけではなく、冒頭の重複H3タイトル削除とタグ抽出（ADR-0007、ADR-0010）も含む。画像のない記事は入口の条件で弾かれ、3つとも実行されない。

実際に「音声入力で日記を書く」（202608/c78002b9）が取りこぼされ、重複H3が残り `tags: []` のまま公開された。手作業で補ったが、画像なしのMedium記事が来るたびに再発する。

## 決定

処理対象の条件に「インポート以降まだ誰も手を入れていない記事」を OR で追加する。

判定は git 履歴で行う。`content/posts` 配下の全履歴を1回の `git log --no-renames --format=%x00%ae --name-only` で取得し、パスごとのcommitter emailを集める。そのパスに現れるのが `action@github.com`（RSSインポートを行うGitHub Action、ADR-0002）だけなら未処理とみなす。履歴のないファイル（未追跡）も未処理として扱う。

処理後にコミットすればcommitterが変わるため、次回以降は対象から外れる。冪等。

## 結果・影響

- 画像のない記事も重複H3削除・タグ付けの対象になる
- 「タグ再付与済みか」を frontmatter のマーカーで持つ必要がない。記事本文を汚さずに済む
- 処理後にコミットしないと毎回対象に出続ける。処理→確認→コミットという既存の運用が前提

## 却下した代替案

- **`tags:` が空かどうかで判定** — Mediumのタグがそのまま入ってくる記事がある（例: `["bears", "evernote"]`）ため、空判定では拾えない。Mediumのタグはルール未準拠で再付与が必要（ADR-0007）だが、Claudeが付け直したタグと区別がつかない
- **frontmatterに処理済みマーカーを追加** — 記事の正本にツール都合のフィールドが増える。git履歴で同じ判定ができる
- **画像条件を単純に外して全Medium記事を対象にする** — 47件すべてが毎回タグ抽出対象になり、処理済みの記事を無意味に再処理する
